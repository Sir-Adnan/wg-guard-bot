# Configuration

Project settings live in two places:

| Where | What | Needs a restart? |
|---|---|---|
| The `.env` file | Infrastructure: tokens, database, port, currency | **Yes** |
| Admin panel → Shop settings | Shop behaviour: prices, trial service, notifications | No |

---

## 1) `.env` variables

### Core

| Variable | Default | Description |
|---|---|---|
| `APP_NAME` | Persian for "VPN Shop" | Shop display name (`.env.example` ships the Persian default) |
| `ENV` | `production` | `production` / `development` / `test` |
| `DEBUG` | `false` | Debug mode |
| `TIMEZONE` | `Asia/Tehran` | Time zone used to render Jalali dates |
| `LOG_LEVEL` | `INFO` | `CRITICAL` … `DEBUG` |
| `SECRET_KEY` | — | **Required.** 64 hex characters. Changing it invalidates every encrypted secret |

### Telegram

| Variable | Default | Description |
|---|---|---|
| `BOT_TOKEN` | — | Bot token from [@BotFather](https://t.me/BotFather) |
| `BOT_MODE` | `polling` | `polling` (no domain) or `webhook` (requires SSL) |
| `WEBHOOK_BASE_URL` | — | Webhook mode only, for example `https://bot.example.com` |
| `WEBHOOK_SECRET` | Automatic | Secret webhook path; generated by `install.sh` |
| `BOT_API_SERVER` | — | Local Bot API server (optional) |
| `BOT_PROXY` | — | Proxy, for example `socks5://127.0.0.1:1080` |

### Database

| Variable | Default | Description |
|---|---|---|
| `POSTGRES_HOST` | `db` | Service name in docker-compose |
| `POSTGRES_PORT` | `5432` | Port |
| `POSTGRES_DB` | `wgguard` | Database name |
| `POSTGRES_USER` | `wgguard` | User |
| `POSTGRES_PASSWORD` | — | Password (generated by `install.sh`) |
| `DATABASE_URL` | — | If it is set, the rest are ignored |
| `DB_POOL_SIZE` | `10` | Connection pool size |
| `DB_MAX_OVERFLOW` | `20` | Extra connections |
| `DB_ECHO` | `false` | Print queries to the log |

### Redis

| Variable | Default | Description |
|---|---|---|
| `REDIS_URL` | `redis://redis:6379/0` | Conversation state and rate limiting. **Optional** — without it the bot falls back to in-memory storage |

### Admin panel

| Variable | Default | Description |
|---|---|---|
| `PANEL_ENABLED` | `true` | Enable the web panel |
| `PANEL_HOST` | `0.0.0.0` | Bind address |
| `PANEL_PORT` | `8080` | Port |
| `PANEL_BASE_URL` | `http://localhost:8080` | Public URL used to build links |
| `PANEL_BEHIND_PROXY` | `false` | Set to `true` if you are behind Nginx, Caddy or any TLS terminator |
| `DOMAIN` | — | Domain or subdomain to serve (no scheme, no path). Empty = no TLS, long polling, no Caddy container |
| `ACME_EMAIL` | — | Contact address for Let's Encrypt. Optional: the certificate is still issued, you just get no expiry notice |
| `PANEL_BIND` | `0.0.0.0` | Host interface the app port binds to. With a domain, `127.0.0.1` keeps it off the public interface |
| `OWNER_USERNAME` | `admin` | Panel login of the owner account |
| `OWNER_PASSWORD` | — | Applied at start, and only while the account has no password. Change it later with `python -m app.cli set-password` ([deployment](DEPLOYMENT.md#reset-owner-password)) |
| `ADMIN_IDS` | — | Numeric admin IDs, comma-separated |
| `SUPPORT_IDS` | — | Numeric support-agent IDs |

### Shop and payment

| Variable | Default | Description |
|---|---|---|
| `CURRENCY_DISPLAY` | `toman` | `toman` or `rial`. **Storage is always Rial** |
| `CARD_TO_CARD_ENABLED` | `true` | Card-to-card payments |
| `WALLET_ENABLED` | `true` | Wallet |
| `TEST_SERVICE_ENABLED` | `true` | Trial service |
| `TEST_SERVICE_COOLDOWN_DAYS` | `30` | Allowed gap between two trial services |
| `RECEIPT_EXPIRE_MINUTES` | `90` | How long a receipt stays valid |
| `MIN_DEPOSIT_RIAL` | `500000` | Minimum wallet top-up (50,000 Toman) |
| `REFERRAL_PERCENT` | `0` | Referral reward percentage |
| `SUBSCRIPTION_BASE_URL` | — | Public domain for subscription links |

### Backups and advanced

| Variable | Default | Description |
|---|---|---|
| `BACKUP_ENABLED` | `true` | Automatic backups |
| `BACKUP_INTERVAL_HOURS` | `24` | Backup interval |
| `BACKUP_KEEP` | `7` | Number of copies kept |
| `WG_REQUEST_TIMEOUT` | `30` | Request timeout to the panel (seconds) |
| `WG_CONNECT_TIMEOUT` | `10` | Connect timeout |
| `WG_MAX_RETRIES` | `3` | Number of retries |

## 2) Shop settings (from the panel)

These values are stored in the database and take effect immediately.

### Group "Shop"

| Setting | Default | Description |
|---|---|---|
| Shop name | From `APP_NAME` | Used as `{shop}` in bot texts |
| Support ID | — | Without the `@` |
| Support hours | Every day, 9:00–23:00 | Display only |
| Maintenance mode | Off | Only admins can access |
| Maintenance message | Empty (built-in text) | Shown while maintenance mode is on |
| Receipt deadline | 90 minutes | |
| Minimum wallet top-up | 50,000 Toman | |
| Referral reward | 0% | |
| Referral programme | On | Shows the referral button in the profile |
| **Purchase cashback** | 0% | Percentage returned to the wallet automatically |
| Gift code | On | Shows the button in the menu |
| Connection guide | On | Shows the button in the menu |
| Special offer | On | Shows the special-plan button |
| Show categories | On | |
| **Traffic unit** | `1024³` (binary) | How many bytes one "GB" in a plan means. The WG-Guard panel prints decimal gigabytes, so under the default a 50 GB plan shows up there as 53.7 GB — the same traffic, two units. Switching to `1000³` makes both read 50; it applies to every plan pushed to a node afterwards |

### Group "Payment"

| Setting | Description |
|---|---|
| Card-to-card payment | Show or hide this method |
| Wallet payment | Show or hide |
| Discount code | Enable the discount-code field at checkout |
| Require a tracking number | When on, a receipt cannot be submitted without a tracking number |

### Group "Trial service"

| Setting | Default |
|---|---|
| Enabled | On |
| Volume (GB) | 1 |
| Duration (days) | 1 |
| Allowed gap (days) | 30 |
| Device count | 1 |
| Dedicated panel | Automatic selection |

> The trial plan is created automatically; you do not need to create it by hand.

### Group "Mandatory membership"

| Setting | Description |
|---|---|
| Mandatory membership | **Master switch.** Until it is on, channels are not checked |
| Re-check interval (minutes) | Reduces the number of requests to Telegram |

### Group "Notifications"

Notifications to admins (new order / receipt / ticket / error / user) and notifications to users
(expiry reminders, usage warnings) plus "remind a few days in advance".

### Group "Appearance and buttons"

| Setting | Default | Description |
|---|---|---|
| Button colours | On | Requires Bot API 9.4+ |
| Premium emoji | On | Requires a Fragment username for buttons |
| Plans per row | 1 | Keyboard layout |
| Show price in the list | On | |
| **Physical keyboard** | Off | Draws the main menu as a Telegram *reply* keyboard under the input field, so it survives scrolling. It carries the same buttons, in the order set on the buttons page, and a press opens the same screen. Customers can hide it with `/keyboard off` and bring it back with `/keyboard` |

### Group "Advanced" (owner only)

| Setting | Description |
|---|---|
| Panel selection method | Automatic / priority / round-robin |
| Public subscription link URL | If it uses a separate domain |
| Maximum open orders per user | Default 3 |
| Welcome image | Telegram `file_id` |
| Log channel | Numeric channel ID for recording events |

---

## 3) Important notes

- **Do not change `SECRET_KEY`.** Panel tokens, WireGuard configs and subscription
  links are encrypted with it. If you do change it, enter the panel token again.
- **Amounts are entered in Toman in the panel** but stored in Rial in the database.
  Keep this in mind when you read the database directly.
- Changes to `.env` need `docker compose up -d` (or `restart`) to take effect;
  panel settings apply immediately.
